# 数据驱动前馈补偿模型 —— 架构设计文档

> 状态：架构级设计（数据尚未接入，本阶段只定架构与接口，不做数值训练）。
> 适用对象：绳驱 2-DOF 球关节（pitch 绕 X、yaw 绕 Y），含动捕 / IMU / 绳张力三类传感器。

---

## 1. 背景与目标

### 1.1 三阶段路线（修订版）

原路线：

| 阶段 | 内容 |
| --- | --- |
| 一 | 基于动捕绝对位姿反馈的闭环控制（基础模型） |
| 二 | 用闭环模型在工作空间探索，采集传感器数据 |
| 三 | 训练数据驱动前馈模型，为闭环加入前馈补偿 |

修订后的路线（见 §8）：**开环探索可跳过"先做闭环"，闭环从"阶段一的门槛"重排为"最终集成 + 安全兜底"**。

| 阶段 | 内容 | 交付物 |
| --- | --- | --- |
| 一′ | 开环激励 + 安全监护，采集 I/O 数据 | 前向模型 `F: u → q` |
| 二′ | 用 F 引导扩大工作空间采集（主动学习） | 覆盖工作空间的数据集 |
| 三′ | 经 F 反解训练逆策略 `g`，套反馈 PID 外壳 | 前馈 + 反馈控制器 |

### 1.2 核心目标

给现有（或未来）的闭环控制加入**数据驱动前馈补偿**，使真实系统在保留反馈扰动抑制能力的同时，具备跟踪参考轨迹（含其导数）的能力。前馈补偿要替代当前"理想几何 IK"中不准确的成分。

## 2. 约束与假设

1. **数据格式冻结**：`mocap_data.csv` / `imu_data.csv` / `force_data.csv` / `servo_data.csv` 的字段不再变化。所有前馈建模的输入输出接口钉死在这套 CSV 上。
2. **张力 = 隐状态，无物理映射**：力传感器输出**不能**换算成球杆真实受到的力矩，仅作为系统的某一隐状态观测使用（见 §5）。
3. **几何 IK 不可信**：`control_model/geometric_ik.py` 的理想几何模型（大圆弧 + 刚性缆 + 18mm 线性卷绕 + 无摩擦/柔度/迟滞）与实际系统偏差大。IK 从"必须正确的底座"降级为"可选弱先验"（见 §7）。
4. **开环数据可采但尚未采**：当前没有可用的开环探索数据，探索策略在 §9 单独设计。

## 3. 现状梳理：闭环为何不达标

当前代码里有两套并存控制器：

- **套件 A**：`control_model/base_PID/pid_controller.py`（IK 前馈 + 任务空间 PID），由 `data_collection` 调用。
- **套件 B**：`feedback_control/`（无 IK、无缆长模型，两个独立 PID → 对侧耦合）。

从代码可确认的闭环不达标根因：

1. **名义模型只含理想几何**：无摩擦、缆绳柔度、松弛、舵机动态、迟滞、反冲。
2. **反馈延迟**：`PyGetLastFrameOfMocapData()` 轮询"最后一帧" + Nokov 解算延迟，纯反馈在动态轨迹下天然滞后。
3. **方向/符号靠实机试出来**：`feedback_control/main.py` 硬编码 `FLIP_PITCH/FLIP_YAW=True`，说明 IK 的符号约定与真实接线/舵机方向存在系统性不一致。
4. **PID 增益未整定**：A（Kp≈0.4~0.5）与 B（Kp=3）量级差近 10 倍，且 B 是"每拍积分不乘 dt"的固定频率假设。
5. **预紧口径不一致**：A 用 `pretension_mm`（毫米），B 用 `PRETENSION_DEG`（度）。
6. **刚体匹配语义不一致**：A 按 `rb.id` 匹配，B 按数组下标取，ID 与下标不等时会取错刚体。

这些根因正是前馈模型要补的对象：**静态偏差（符号/gain/耦合）+ 动态滞后（迟滞/松弛/舵机动态）**。

## 4. 总体架构

### 4.1 顶层控制律

```
u(t) = u_ff(t) + u_fb(t)
```

- `u_ff`：数据驱动前馈（本文档主体）。
- `u_fb`：任务空间 PID，仅作扰动抑制与安全兜底，稳态应收敛到接近 0。

前馈有两种形态，对应"IK 是否可信"：

| 形态 | 公式 | 适用条件 |
| --- | --- | --- |
| **残差形态** | `u_ff = u_IK(q_d) + r(q_d, q̇_d, q̈_d, τ, h)` | IK 方向/量级大体可信 |
| **直接逆形态（主推）** | `u_ff = g(q_d, q̇_d, q̈_d, τ, h)`，直接输出完整控制量 | IK 不可信（当前约束下默认） |

两种形态共用**同一个可微前向模型 F**，差别只在"是否在 IK 上叠加"。

### 4.2 两个网络的分工

| 网络 | 符号 | 方向 | 目标 |
| --- | --- | --- | --- |
| 前向动力学模型（surrogate） | `F_θ` | `u → q` | 可微仿真器，提供 `∂q/∂u` |
| 逆模型（策略） | `g_φ` | `q_d → u` | 前馈指令生成 |

**关键认知**：逆向（`g`）没有直接真值，前向（`F`）有（动捕 `q_m`）。因此：

1. 先用动捕数据把 `F` 训好（干净的直接监督）；
2. 再让 `g` 通过**冻结的可微 F** 反传误差，损失目标是期望轨迹 `q_d`。

### 4.3 架构图

```
              ┌─────────── 学习到的前向模型 F（主模型）───────────┐
              │   q_{k+1} = F(q_k, u_k, u_{k-1}, τ_k, h_k)      │
              └──────────────────────┬──────────────────────────┘
                                     │ 可微，提供 ∂q/∂u
                                     ▼
               逆解（二选一，都不依赖 IK 数值）：
               (A) 在线反解：每拍解带约束 QP（MPC / Gauss-Newton）
               (B) 摊销反解：训练逆策略 g，经 F 反传，推理飞快
                                     │
                                     ▼
               u = decode(d_pitch, d_yaw, c_1, c_2)   （差分/共模重编码）
                                     │
                                     ▼
                        物理舵机  +  PID（兜底/扰动抑制）
```

## 5. 传感器角色分工

| 传感器 | 角色 | 用法 |
| --- | --- | --- |
| 动捕 | 慢但准的真值 / 监督 | 训练标签 `q_m`；对齐基准；验证评估 |
| IMU | 快、低延迟的导数特征 | 校准后姿态 `q_i` + 陀螺 `ω_i` 作 `q̇`、线加速度 `a_i` 作 `q̈` 代理 |
| 张力 | **隐状态观测，无物理映射** | 见下 |
| 舵机指令 | 控制输入观测 | F 的输入；`u(k−1)` 作迟滞/反冲记忆 |

### 5.1 张力的两种"无物理意义"用法

1. **松弛检测（只用序数/阈值信息）**：
   - `slack_i = σ(ε − |τ_i|)`（软指示）或 `1[|τ_i| < ε]`。
   - 作为 `g` 的输入特征、训练正则项（防松弛先验）、运行时安全闸。
   - 不需要单位/物理标定，只需"哪根缆快松了"。
2. **隐状态辅助监督（进阶）**：
   - 在状态空间模型里把 `τ` 作为辅助重构输出 `τ̂`，逼隐状态对"张紧程度"敏感。
   - 同样不做物理力矩映射。

## 6. 前向模型 F 的训练

### 6.1 输入

一段历史窗口（teacher forcing）：

```
s_k = [ q_m(k), q_m(k−1), …, q_m(k−m+1),      # 真实姿态历史
        u(k),   u(k−1),   …, u(k−n+1) ]       # 指令历史
      (可选) + [ ω_imu(k) ]                     # 陀螺作速度先验
      (可选) + [ τ(k) ]                         # 张力作隐状态观测
```

### 6.2 输出与 ground truth

```
Δq̂_k = F_θ(s_k)             # 预测 q(k+1) − q(k)
q̂_{k+1} = q_m(k) + Δq̂_k     # teacher forcing
```

**ground truth = 动捕 `q_m(k+1)`**，是直接观测、干净的标签。

### 6.3 损失与反传

```
L_F = (1/N) Σ_k ‖ q̂_{k+1} − q_m(k+1) ‖²
```

直接监督：`∂L_F/∂θ = ∂L/∂q̂ · ∂F/∂θ`。前向映射（4 输入 → 2 输出）是**良定**的，不存在"4 缆驱动 2 DOF"的冗余病态（冗余只存在于逆向）。

> **易踩坑**：F 用 teacher forcing 训练，但后续被 `g` 调用时会 free-running（误差累积、漂移，即 exposure bias）。因此 F 训练应加入**多步 rollout loss**（从真实起点跑 N 步、累计误差），而非只训单步。

## 7. 逆模型 / 残差模型的训练

### 7.1 执行器重编码（比 IK 更底层、与几何无关）

与几何模型无关的硬件事实：4 缆为对抗对（pitch 对 = 缆 1↔3，yaw 对 = 缆 2↔4）。据此做**固定、可逆、可微**的线性重编码：

```
d_pitch = u[0] − u[2]      # 一对缆的差动 → 驱动 pitch
d_yaw   = u[1] − u[3]      # 一对缆的差动 → 驱动 yaw
c_1     = u[0] + u[2]      # 一对缆的共模 → 张紧/预紧（冗余自由度）
c_2     = u[1] + u[3]
```

- **差分 `d`（2 维）≈ 2 DOF**：真正要被学习的运动指令。
- **共模 `c`（2 维）= 零空间冗余**：只负责"缆绳绷紧、不松弛"，不参与运动学。

这个重编码把"4→2 冗余"显式解耦：运动由 `d`（良定）决定，冗余由 `c` 显式调度。它是 `use_ik_feedforward=False` 的"直接差分"模式的泛化（把标量 `direct_gain` 换成学习到的映射）。

### 7.2 输入 / 输出

```
输入 x_k = [ q_d, q̇_d, q̈_d, τ, slack(τ), u(k−1) ]   (+ 可选 IK 特征)
隐藏 h_k = GRU_φ(h_{k−1}, x_k)                        （可选，序列形态）
输出     = [ d_pitch, d_yaw, c_1, c_2 ]                （或只输出 d，c 用固定预紧）
解码 u   = pair_decode(d, c)
```

维度参考：`q_d(2) + q̇_d(2) + q̈_d(2) + τ(4) + slack(4) + u_prev(4) = 18`；`h` 取 32~64。

### 7.3 逆模型没有"正确 u"，误差从哪来

**数据里不存在"能让系统精确到达 q_d 的正确指令"这一列。** 因此有两种构造机制：

#### 机制 A —— 经验残差监督（仅限收敛闭环数据，可选预训练）

当闭环已收敛（`e = q_d − q_m ≈ 0`）时，日志里记录的 `u_log(k)` 恰好是"维持 q_d 的那条指令"：

```
Δu^gt_k = u_log(k) − u_IK(q_d(k))
L_S = (1/T) Σ_k ‖ Δu_k − Δu^gt_k ‖²
```

- 直接监督、稳定、收敛快；
- 只适用于误差≈0 的片段，学到的是"PID 实际做的"，外推弱。

#### 机制 B —— 经可微前向模型反传（主推，通用）

不直接给 `g` 一个 u 目标，而是让 `g` 输出指令序列，塞进**冻结的 F** 仿真出姿态，与期望轨迹比较：

```
1. u_k = u_IK(q_d(k)) + Δu_k       （或直接 u_k = decode(g(x_k))）
2. q̂_{k+1} = F(q̂_k, u_k, u_{k−1}, …)    # F 自由跑
3. L_I = (1/T) Σ_k ‖ q̂_k − q_d(k) ‖²
        + λ_u Σ_k ‖Δu_k‖²                 # 残差/指令幅度正则
        + 防松弛 / 平滑项（可选）
```

**可反向传播的原因**（链式法则逐项）：

```
∂L_I/∂φ = Σ_k  ∂L_I/∂q̂_k · ∂q̂_k/∂u_{k−1} · ∂u_{k−1}/∂Δu_{k−1} · ∂Δu_{k−1}/∂φ
            └ q̂−q_d  ┘  └ F 的雅可比 ┘  └ 加法≈I  ┘  └ 网络梯度 ┘
```

- `∂L_I/∂q̂_k = 2(q̂_k − q_d(k))`：监督信号，目标是已知的 `q_d`。
- `∂q̂_k/∂u = ∂F/∂u`：F 是可微网络，autograd 自动给出"指令如何影响姿态"。
- 结论：**不需要知道"正确的 u"，可微 F 替代了它；误差从 `q̂` 一路反传回 `g`。**

该机制还绕开了逆向冗余病态：`g` 每次只被要求"在 F 的局部线性化下让 q̂ 靠近 q_d"，F 的雅可比自然投影掉 4 维 u 里多余的自由度。

### 7.4 递归模型的训练特殊点

1. **BPTT**：把长度 T（1~2s）的轨迹展开，损失在窗口末尾求和后沿 `h` 链回传。`h_0` 零初始化，窗口间保持 `h` 连续（截断 BPTT + detach）。
2. **`u(k−1)` 与 `h` 双通道记忆**：`h` 承载慢变隐状态（张紧/摩擦/负载），`u(k−1)` 承载快变的一拍历史（方向、是否刚换向），共同表达迟滞/反冲/松弛。

## 8. IK 不可信时的降级方案

### 8.1 IK 的三个角色与替代

| IK 提供的角色 | 不可信后的处置 |
| --- | --- |
| 名义前馈底座 | ❌ 底座歪则弃用，改由 `g` 直接输出完整控制量 |
| 4→2 冗余规范化解 | ❌ 改由显式共模 `c` / 防松弛 QP 处理 |
| 逆解初始化 | ⚠️ 可信则当热启动初值，否则弃用 |
| `∂u/∂q` 结构先验 | ❌ 由数据学出的 F 提供 `∂q/∂u` |

### 8.2 逆解两种形态（均不依赖 IK 数值）

**(A) 在线反解（MPC / Gauss-Newton，开发与安全校验）**：

```
minimize_{u_0..u_H}  Σ ‖ F(q̂_k, u_k) − q_d(k) ‖² + λ_u ‖Δu_k‖²
subject to           |d| ≤ d_max,  slack(τ) ≤ 0
```

2-DOF 下每拍几步 Gauss-Newton（4×2 雅可比），计算量极小，约束可硬编码（最安全）。

**(B) 摊销反解（部署，推理快）**：训练 `g`，经冻结 F 反传，损失目标 `q_d`（见 §7.3 机制 B）。

**推荐组合**：部署用 B，开发/安全校验用 A，两者共用同一个 F。

### 8.3 IK 的弱先验用法（按可信度递减）

| IK 可信度 | 用法 |
| --- | --- |
| 只有 gain/耦合错，符号方向大体对 | 作为 (A) 在线反解初值 |
| 符号不确定，但"哪对缆对应哪轴"仍成立 | 只把 `u_IK(q_d)`、`J_IK(q_d)` 当输入特征 |
| 完全不可信 | 彻底不喂，靠差分重编码 + F 反解 |

**客观判定方法**：用 `calibrate_direct_gain` 或开环小扰动实测每轴局部雅可比符号/量级，与 `GeometricIK.jacobian()` 对比。

## 9. 探索与数据采集策略（开环，可跳过闭环）

### 9.1 为什么开环数据更适合 F

闭环数据里 `u` 是对 `q_m` 误差的反应，动捕噪声/延迟使 `u` 与噪声相关，辨识产生偏置。开环数据中 `u` 是主动设计、精确已知的激励，与测量噪声独立，`(u, q_m, τ, imu)` 是干净因果 I/O 对。

### 9.2 必须保留的三样（不是"闭环控制"）

| 保留项 | 原因 | 是否=闭环 |
| --- | --- | --- |
| 动捕实时读 `q_m` | F 的唯一真值 + 安全监护输入 | 仅观测，不控制 |
| 安全监护器 | 开环会推向限位/干涉，需超限急停回中 | 监督器，非反馈控制器 |
| 缆绳预紧（共模）策略 | 缆只能拉不能推，无预紧会松弛失控 | 开环共模调度 |

### 9.3 激励信号设计（从零指令附近逐步扩张）

1. 单轴/双轴**小幅度 dither / 伪随机差分**（覆盖低频→中频）；
2. **chirp / multisine**（扫频，覆盖频带）；
3. **小阶跃 + 停留**（暴露静摩擦、蠕变、松弛）；
4. **预紧扫描**（同一激励在不同共模下重复）。

> 因 IK 不可信，不能再用大范围 IK waypoint 开环扫频（会推向限位）。改为：小差分先辨识**零点前向雅可比** → 得到局部可信 F → 用 F 反解规划更大运动 → 滚雪球式扩展工作空间。

### 9.4 现有代码支持度

已支持：`OpenLoopController`、`_run_calibration_sweep()`（正弦扫频+记录）、`calibrate_direct_gain.py`（小差分开环辨识）、`servo_data.csv` 已落盘 `servo_*_target_deg + target/current pitch/yaw`。

待补：开环激励控制器（dither/chirp/multisine/阶跃 + 共模调度）、独立安全监护线程。

## 10. 数据处理管线

```
mocap_data.csv ─┐
imu_data.csv   ─┼─ merge_asof(pc_timestamp_ns, 50ms) ─▶ 统一时间轴(重采样 100~200Hz)
force_data.csv ─┤                                        │
servo_data.csv ─┘                                    特征工程 ─▶ 样本
```

- 统一时钟：同进程产生，`pc_timestamp_ns` 直接对齐（现有 `merge_asof` 已实现）。
- 慢流上采样：张力 ~10Hz → 前向填充/零阶保持到控制频率。
- IMU 校准：复用 `IMU_alignment.calibrate_linear`（`q_m ≈ A·[q_i_p, q_i_y] + b`），陀螺作 `q̇`。
- 样本结构：

```
X: { q_d, q̇_d, q̈_d, q_m(仅监督/特征), q_i(校准后), ω_i, a_i, τ, slack(τ), u_{t-1} }
y: { u（实际指令）或 Δu = u − u_IK(q_d) }
```

- **切分必须按轨迹/会话留出（leave-one-trajectory-out）**，不能随机 shuffle，否则时间泄漏虚高验证指标。

## 11. 训练 / 验证 / 评估

### 11.1 训练循环（伪代码）

```python
# 1. 前向模型 F_θ
for batch in dataloader_openloop:            # (s_k, q_{k+1}) 来自开环 I/O
    q_next_pred = F(batch.s)
    loss = mse(q_next_pred, batch.q_next)    # GT = 动捕 q_m(k+1)
    loss.backward(); opt_F.step()

# 2a. 逆模型 g_φ：机制 A（经验残差，可选预训练）
for seg in converged_closedloop_segments:
    for k in range(seg.T):
        dU_pred = g(x_k, h_{k-1})
        dU_gt   = seg.u_log[k] - IK(seg.q_d[k])
        loss += mse(dU_pred, dU_gt)
    loss.backward(); opt_g.step()

# 2b. 逆模型 g_φ：机制 B（rollout，主推）
F.eval()
for traj in desired_trajectories:
    q_hat, h, u_prev = traj.q_start, zeros(), None
    for k in range(traj.T):
        u  = IK(traj.q_d[k]) + g(x_k, h)     # 或 u = decode(g(x_k))
        q_hat = F(q_hat, u, u_prev)
        loss += mse(q_hat, traj.q_d[k])
        u_prev = u
    (loss/T + reg).backward()                # 经 q_hat→u→g 回传
    opt_g.step()
```

### 11.2 评估闭环（逐步加严）

1. **离线拟合**：验证集 `u` 预测 MSE；经 F 间接评估 `q_pred` 的 MAE/RMSE。
2. **离线闭环仿真**：用 F 当被控对象，跑 `u = u_ff + u_fb`，测跟踪误差（不上硬件调结构/增益）。
3. **真机闭环**：`u = u_IK + r + PID`（或 `u = g + PID`）实机跑，用 `valuation.py` 出 MAE/RMSE/最大误差。
4. **附加指标**：张力最小值/松弛时长、指令变化率（防抖）。
